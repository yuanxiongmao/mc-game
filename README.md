# 方块侦探 · MC 猜方块

双击 **启动游戏.cmd** 或 **index.html** 即可在浏览器离线游玩。无需安装依赖，所有资源在本目录中。

如果已安装 Node.js，也可在本目录运行 `node server.cjs`，然后访问 http://127.0.0.1:4173 。用同一个地址游玩可稳定保存进度。浏览器禁止本地存储时仍可玩，但刷新不保留进度。

## 玩法

打开页面后先点击“开始游戏”，系统才随机选择一个**方块类别**并启用猜测。未开始时不能提交，也不会预选目标。玩家输入一个字段并直接提交，不会出现补全、候选列表或图鉴选题。系统自动选出名称最匹配的方块，并将它作为本次猜测。

完整名称优先，其次比较名称片段，再比较错别字相似度；支持中文、英文 ID 和原始变体名称。例如“闪长”匹配“闪长岩”，“黑曜是”匹配“黑曜石”，“橡木原木”仍归入“原木”。选择过程不参考隐藏答案或已猜记录，同分按固定规则选择。

每次展示全部 11 项汇总属性：可再生、挖掘工具、发光性质、完整方块、可燃、火焰传播、透明、堆叠数量、爆炸抗性、硬度、初始版本。

探索记录采用自适应紧凑列表：桌面将方块信息和全部属性排在同一行，手机将属性紧凑换行，缩小图片和间距，让一屏显示更多次猜测，均无需水平滚动。每次猜测同时展示本地方块图片、名称及完整的原始输入；合并类别标注“代表外观”，空气等不可见方块展示示意图并注明“无可见外观”。所有图片随项目保存，离线可用。

绿色 ✓ 表示汇总属性匹配，红色 × 表示不同。爆炸抗性、硬度、版本的 ↑ 表示答案更高或更新，↓ 表示答案更低或更早。爆炸抗性和硬度的范围取中点作为参考值：最低值 +（最高值 − 最低值）÷ 2。答案和猜测均按参考值比较方向，即使范围交叉也会提示高低；参考值相同则无箭头，不显示重叠提示。

每次有效非空提交都计为一次猜测，重复匹配到同一个方块也计数，不会自动跳过。空输入不计数，字段最多 80 个字符。记录同时显示原始输入和系统选中的方块；猜中后结束本局。

随时可点击“结束本局，查看答案”，确认后揭晓目标方块并停止本局猜测，不增加猜测次数。原有记录和结束状态会保存，刷新后仍能查看答案；游戏进行中仅保留“结束本局，查看答案”，取消“开始新的一局”和“再来一局”。结束后游戏停止，答案和记录保留；再次点击“开始游戏”才会清空旧记录并选择新的目标。

未开始游戏或本局结束后可点击“方块图鉴”，查看全部方块分类、图片及 11 项汇总属性，支持名称、英文 ID 和变体名称搜索及分页。浏览不会开始游戏或增加猜测次数；开始游戏后图鉴入口关闭。

## 数据口径

保留 **Java 26.3 全部 1286 个原始方块**的数据，游戏中归并为 **342 个类别**。每个原始方块只属于一个类别，没有删除变体；只是改为按大类显示、比较和选题。范围不包括模组、基岩版独有方块及 26.3 中已经移除的方块。

| --- | --- |
| 普通、连锁型、循环型命令方块 | 命令方块 |
| 普通空气、洞穴空气、虚空空气 | 空气 |
| 各木种原木、木头、菌柄、去皮变体及竹块 | 原木 |
| 各木种木板、竹马赛克 | 木板 |

| 各材质的门、活板门、按钮、压力板、栅栏、墙等 | 分别显示门、活板门、按钮、压力板、栅栏、墙等 |

| 石英、海晶石、朱砂、硫黄的普通及加工变体 | 各自归并到对应基础材质 |

红石、红色蘑菇等不是染色变体，不会因名称带颜色被误合并；矿石及其他独立资源方块保留。

铜楼梯、铜台阶、铜门等继续沿用已有的大类规则。盆栽没有独立题目，且不会把花盆的硬度、堆叠和碰撞体等属性混入植物的汇总属性。雕纹名称也兼容“雕文”的输入写法。

- 初始版本按大类最早出现的成员归入主版本：`pre-alpha`、`alpha`、`beta`、`1.8`、`1.17`、`26.3` 等，不显示快照号和第三段小版本。`pre-alpha` 包含 rd、Classic、Indev 和 Infdev；例如原木为 `pre-alpha`，紫水晶块为 `1.17`。快照依据其所属正式更新归类，而不误用同时维护的旧版本补丁。
- 工具只比较“镐、斧、锹、锄、剪刀、剑、任意、不可挖掘”等大类。铁矿石、金矿石、黑曜石都显示“镐”，不再比较镐的材质等级。
- 同类成员的工具合并显示，如门为“镐/斧”，楼梯因包括羊毛变体而为“镐/斧/剪刀”。比较的是整个工具集合，而非只要有一种相同就匹配。
- 可再生、完整、可燃、火焰传播、透明和发光性质：所有成员具备则为是/发光，都不具备则为否/不发光；组内有差异则为“部分”。比较汇总结果，“部分”和“部分”匹配。
- 堆叠数量、爆炸抗性、硬度组内不同时显示最小值到最大值。相同范围匹配；爆炸抗性和硬度的方向按双方范围中点比较。中点相同但范围不同，仍标红且无箭头。
- 基础属性采用 26.3 中默认方块状态。发光判断默认状态是否发光，不取激活后的最大亮度；透明性采用游戏的面遮挡分类（`can_occlude` 为 false 视为透明），完整方块按默认碰撞体积判断，两者独立。
- 无物品形态的技术方块显示“无物品形态”，不假定可堆叠 64 个；堆叠数量读取对应物品的真实上限。
- 不可破坏方块的内部硬度为 -1，界面显示“不可破坏”，方向比较视为高于所有可破坏方块。
- 可燃指可被火破坏；火焰传播指可促进火向该方块蔓延，均按有无比较。不把永久燃烧或熔岩引燃视为传播。
- 再生性参考当前 Wiki 的 Java 版条目与默认形态，按有无判断，与初始版本时是否可再生无关。饰纹陶罐按无纹饰形态、幽匿尖啸体按非召唤监守者形态记录。传送门的可再生指能否重新产生对应方块，不是能否获得物品。

完整资料来源和生成方式见 [SOURCES.md](SOURCES.md)。图标为程序绘制的像素方块示意，并非官方材质。非 Minecraft 官方作品。

## 自动匹配与存档

界面不提供选择列表和输入提示。输入 `black_concrete_slab` 直接提交为“楼梯”，输入“红色染色玻璃”直接提交为“玻璃”。即使没有明显相关的名字，也会选择评分最高的方块并计数。匹配采用字符串包含关系与编辑距离，不调用在线模型。

旧分类模式存档会先按原来的归并规则恢复，再升级到新玩法。新玩法保存每一次输入及重复猜测，刷新后不会去重；若分类合并使历史猜测命中答案，则在首次命中处结束。更早的具体方块模式存档不混入、不删除。

## 文件和验证

`data.js`：1286 个原始方块；`catalog.js`：归并规则和属性聚合；`version-groups.js`：主版本映射；`core.js`：比较和回合逻辑；`app.js`：界面与保存。

运行 `node --test tests/*.test.cjs` 验证原始题库完整性、全部变体归并、天然石材独立、工具集合、“部分”属性、数值范围、主版本、自动匹配、重复计数和新旧存档兼容。

Windows 安装 Microsoft Edge 时，可运行 `node tests/browser-check.cjs` 检查无提示输入、回车直接提交、字段自动匹配、重复计数、原始字段显示、猜中结束、进度恢复和手机布局。该命令使用本目录的独立测试配置，不使用玩家的浏览器配置，并更新预览图。

离线重建：依次运行 `node scripts/review-overrides.cjs`、`node scripts/build-data.cjs`、`node scripts/build-version-groups.cjs`。原始资料均保存在 `sources/` 中；运行时由 `catalog.js` 自动产生分类题库。
